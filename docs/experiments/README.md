# PlayerLab experiments

Each directory or experiment note answers one sharply bounded question which Player2 must not absorb prematurely. A result can promote a small, documented seam into Player2, become a standalone plugin after a second consumer appears, or be deleted.

| Experiment | Question | Status | Promotion rule |
| --- | --- | --- | --- |
| [companion-body-spike.md](companion-body-spike.md) | Does a visible game-world body add enough relationship value to justify custom-NPC complexity? | Proposed | Only after Player2's marker-based result has been tested |
| [shadow-farmer-spike.md](shadow-farmer-spike.md) | Can a second game entity safely perform one real tool action without impersonating a multiplayer player? | Proposed | Only if it survives reload and the body spike proves insufficient |
| [multiplayer-semantics-spike.md](multiplayer-semantics-spike.md) | Is a real farmhand session valuable enough to justify its connection and save lifecycle? | Proposed | Only with a multiplayer-specific player need |

## Experiment contract

Every executable experiment must add its own folder and README before code. State the question, environment, exact command, evidence, success signal, teardown rule, and destination. Do not add a generic runtime, shared model client, or game adapter for an unanswered question.
